## Profile findings and changes

- Container validation and `ParsedBom::parse` remain separate by design: the complete checked-range
  pass must finish before the upstream container parser runs. The hostile block-count result shows
  that this early rejection path remains about five microseconds; percentage changes at that scale
  are timer noise rather than material additional work.
- Checked block lookups remain in validation. The typed-block scenario showed that most incremental
  cost was Python projection rather than range checking, so no unchecked lookup shortcut was added.
- Root and linked path blocks still use explicit cycle sets and checked traversal. Their work is
  isolated by the cycle scenario and remains bounded by block and path limits.
- Validation now records a safe path plan. Materialization consumes that plan and creates each full
  path once instead of asking the upstream implementation to rebuild the ancestor chain. Repeated
  variables which reference one tree reuse the native path vector.
- Lossless file/link names now flow through borrowed `Cow` values, symbolic modes use a stack buffer,
  and raw hex remains opt-in because its required output copy is measurable in the raw-block case.
- Python field names and enum-like values are interned, and lists are allocated at their exact final
  length. This accounts for the large reduction in retained Python allocation and RSS while keeping
  the projected string payload unchanged.

No release was published from the mutable candidate tree. The release workflow remains tag-only,
pins Rust 1.98.1 for wheel and sdist jobs, verifies tag/package versions, and publishes the artifacts
associated with the immutable event commit through the protected `pypi` environment.
